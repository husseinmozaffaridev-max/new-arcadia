# منبع منطق برنامه (Arcadia MBSE Methodology Source of Logic)

این سند مرجع رسمی و استخراج‌شده از مستندات لاجیک متدولوژی Arcadia (مبتنی بر ۹ تصویر دست‌نویس پروژه) است که در سراسر پروژه New Arcadia به عنوان قانون و منطق بنیادین رفتار نرم‌افزار، دیاگرام‌ها، قوانین اتصال و ساختار شکست عناصر ملاک عمل قرار می‌گیرد.

---

## ۱. نقشه راه و کلیات روش‌شناسی Arcadia
متدولوژی Arcadia شامل ۴ لایه اصلی مهندسی سیستم مبتنی بر مدل (MBSE) است:
1. **تحلیل عملیاتی (Operational Analysis - OA)**
2. **تحلیل سیستمی (System Analysis - SA)**
3. **معماری منطقی (Logical Architecture - LA)**
4. **معماری فیزیکی (Physical Architecture - PA)**

علاوه بر این ۴ لایه، مفاهیم مشترکی مانند سناریوها (Scenarios)، نمودارهای کلاس داده (Data Class Diagrams - CDB)، و پورت‌ها (Ports) در سراسر لایه‌ها کاربرد دارند.

---

## ۲. لایه اول: تحلیل عملیاتی (Operational Analysis - OA)
* **پرسش محوری:** کاربران چه نیازهایی دارند و در دنیای واقعی چه می‌کنند؟

### مفاهیم لایه OA:
* **موجودیت عملیاتی (Operational Entity):** موجودیتی در دنیای واقعی که ساختار سازمانی دارد و **می‌تواند تجزیه و شکسته شود** (مانند سازمان، پایگاه، شرکت، واحد عملیاتی).
* **بازیگر عملیاتی (Operational Actor):** نوع خاصی از موجودیت انسانی یا بیرونی که **تجزیه‌ناپذیر (غیرقابل شکستن)** است.
* **قابلیت عملیاتی (Operational Capability):** هدف یا توانایی سطح بالایی که کاربر در راستای مأموریت خود به آن نیاز دارد.
* **فعالیت عملیاتی (Operational Activity):** کارهایی که موجودیت‌ها (Entity) یا بازیگران (Actor) انجام می‌دهند.
* **مأموریت عملیاتی (Operational Mission):** هدف غایی و سطح بالای سازمان یا کاربران.
* **فرآیند عملیاتی (Operational Process):** مجموعه‌ای از فعالیت‌های زنجیره‌ای متوالی برای دستیابی به یک هدف مشخص.

### زنجیره وابستگی در OA:
$$\text{مأموریت (Mission)} \xrightarrow{\text{نیاز دارد به}} \text{قابلیت (Capability)} \xrightarrow{\text{توصیف توسط}} \text{فرآیند عملیاتی (Process)} \xrightarrow{\text{شامل}} \text{فعالیت‌ها (Activities)} \xrightarrow{\text{توسط}} \text{موجودیت‌ها و بازیگرها}$$

### دیاگرام‌های لایه OA (به ترتیب گام ۱ تا ۶):
1. **OEBD / OEB (Operational Entity Breakdown Diagram):** نمودار شکست درختی موجودیت‌ها و ساختار سازمانی.
2. **OCB / OCD (Operational Capability Blank / Description):** تعریف قابلیت‌ها و پیوند مشارکت (InvolvementLink) با موجودیت‌ها، بازیگران و مأموریت‌ها.
3. **OABD (Operational Activity Breakdown Diagram):** ساختار شکست درختی فعالیت‌ها به زیرفعالیت‌ها.
4. **OAIB (Operational Activity Interaction Blank):** تعریف تعاملات و تبادلات تعاملی (OperationalExchange) بین فعالیت‌ها.
5. **OAS / OPD (Operational Activity Scenario / Operational Process Description):** سناریوهای زمانی یا زنجیره فرآیندی برای یک قابلیت خاص.
6. **OAB (Operational Architecture Blank):** معماری جامع عملیاتی؛ نمایش کلیه موجودیت‌ها، بازیگران، تخصیص فعالیت‌ها به موجودیت‌ها/اکتورها (Allocation)، و تبادلات تعاملی میان آن‌ها (OperationalExchange / Communication Mean). بدون شکست ساختاری درون OAB.

## ۳. لایه دوم: تحلیل سیستمی (System Analysis - SA)
* **پرسش محوری:** سیستم برای کاربر چه کاری باید انجام دهد؟ (تعیین مرز سیستم به عنوان جعبه‌سیاه / Black-box)

### قانون اعتبارسنجی و ردیابی (Traceability Warning):
> **هشدار مهم:** اگر یک قابلیت (System Capability) یا بازیگر (System Actor) در لایه سیستم ایجاد شود که هیچ پیوند تحققی (Realization Trace) با لایه قبلی (عملیاتی - OA) نداشته باشد، نرم‌افزار موظف است **Warning** صادر کند.

### مفاهیم لایه SA:
* **سیستم (System):** جعبه‌سیاه تحت طراحی که به نیازهای کاربران پاسخ می‌دهد.
* **کنشگر سیستم (System Actor):** موجودیت‌های خارج از مرز سیستم که با سیستم تعامل دارند (تجزیه‌ناپذیر).
* **مأموریت سیستم (System Mission):** هدف سطح بالایی که سیستم به خاطر آن ساخته می‌شود.
* **قابلیت سیستم (System Capability):** توانایی‌های سیستم جهت تحقق مأموریت‌ها.
* **عملکرد سیستم (System Function):** رفتار یا تابعی که توسط سیستم یا کنشگران انجام می‌شود.
* **تبادل عملکردی (Functional Exchange):** تبادل داده یا سیگنال بین دو عملکرد از طریق پورت‌ها.
* **زنجیره عملکردی (Functional Chain):** مسیر پیوسته از تبادلات عملکردی بین چند عملکرد برای اجرای یک سناریو.

### دیاگرام‌های لایه SA:
1. **CSA (Context System Actors):** مرز سیستم و کنشگران خارجی و تبادلات بین آن‌ها.
2. **MCB / SCD (Mission Capabilities Blank / System Capability Description):** مأموریت‌ها و قابلیت‌های سطح بالای سیستم و مشارکت کنشگران.
3. **SFB / SFBD (System Function Breakdown):** ساختار شکست درختی عملکردهای سیستم.
4. **SDFB (System Data Flow Blank):** جریان داده و تبادلات عملکردی بین توابع سیستم مستقل از ساختار فیزیکی.
5. **SAB (System Architecture Blank):** معماری جامع سیستم؛ سیستم، اکتورها، تخصیص توابع و تبادلات (SystemExchange, ComponentExchange, FunctionalExchange, Allocation).
6. **FS / ES / SS (Functional / Exchange Scenario):** توالی زمانی اجرای عملکردها در یک سناریوی خاص.
7. **FCD (Functional Chain Description):** توصیف مسیر زنجیره عملکردی برای تحقق یک قابلیت یا سناریو.

## ۴. لایه سوم: معماری منطقی (Logical Architecture - LA)
* **پرسش محوری:** سیستم چگونه کار می‌کند؟ (بدون وابستگی به فناوری و سخت‌افزار خاص - How)

### مفاهیم لایه LA:
* **مؤلفه منطقی (Logical Component):** بلوک ساختاری درون سیستم که مسئول انجام مجموعه‌ای از عملکردهای منطقی است.
* **عملکرد منطقی (Logical Function):** رفتار، تابع یا خدمتی که توسط یک مؤلفه منطقی ارائه می‌شود.
* **تبادل عملکردی (Functional Exchange / Logical Exchange):** تبادل اطلاعات بین دو عملکرد منطقی.
* **تبادل مؤلفه (Component Exchange):** ارتباط ساختاری/پروتکلی میان مؤلفه‌های منطقی یا با اکتورها.
* **کنشگر منطقی (Logical Actor):** کنشگر خارج از مرز سیستم در سطح منطقی (تجزیه‌ناپذیر).
* **قابلیت منطقی (Logical Capability):** توانایی تحقق‌یافته توسط مؤلفه‌ها و توابع منطقی.

### دیاگرام‌های لایه LA:
1. **CRB / LCRB (Capability Realization Blank):** نحوه تحقق قابلیت‌های سیستم توسط اجزا و عملکردهای منطقی.
2. **LFB / LFBD (Logical Function Breakdown):** شکست درختی و سلسله‌مراتبی عملکردهای منطقی.
3. **LDFB (Logical Data Flow Blank):** جریان داده و تبادلات عملکردی بین توابع منطقی.
4. **LCB (Logical Component Breakdown):** شکست درختی مؤلفه‌های منطقی.
5. **LAB (Logical Architecture Blank):** معماری جامع منطقی؛ مؤلفه‌های منطقی، اکتورها، تخصیص توابع به مؤلفه‌ها، تبادلات مؤلفه‌ها (`ComponentExchange`) و اینترفیس‌ها (`Provided/RequiredInterface`).
6. **FC / ES / LS (Functional Chain / Scenario):** زنجیره‌های عملکردی و سناریوهای زمانی منطقی.

---

## ۵. لایه چهارم: معماری فیزیکی (Physical Architecture - PA)
* **پرسش محوری:** سیستم چگونه و با چه سخت‌افزار، نرم‌افزار و فناوری‌هایی ساخته خواهد شد؟

### مفاهیم لایه PA:
* **مؤلفه فیزیکی (Physical Component):** قطعه یا واحد واقعی سازنده سیستم.
* **مؤلفه گره (Node PC):** مؤلفه فیزیکی سخت‌افزاری میزبان که منابع پردازشی/اجرایی را فراهم می‌کند (مثل سرور، میکروکنترلر، برد الکترونیکی).
* **مؤلفه رفتاری (Behavior PC):** مؤلفه فیزیکی نرم‌افزاری/رفتاری که روی یک نود مستقر می‌شود (مثل وب‌سرویس، درایور، فریمور).
* **رابطه استقرار (Deployment Link):** پیوندی که مشخص می‌کند کدام مؤلفه رفتاری (Behavior PC) روی کدام نود فیزیکی (Node PC) مستقر است.
* **تبادل فیزیکی (Physical Exchange):** اتصال فیزیکی یا جریان داده اجرایی بین توابع فیزیکی.
* **گذرگاه / پیوند فیزیکی (Physical Bus / Physical Link):** رسانه ارتباطی فیزیکی واقعی میان گره‌ها (کابل اترنت، باس CAN، سریال و...).
* **عملکرد فیزیکی (Physical Function):** عملکرد سطح اجرا که به یک مؤلفه فیزیکی تخصیص داده می‌شود.
* **زنجیره عملکرد فیزیکی (Physical Function Chain):** مسیر پیوسته عملکردهای فیزیکی.

### دیاگرام‌های لایه PA:
1. **CRB / PCRB (Capability Realization Blank):** نمایش نحوه تحقق فیزیکی قابلیت‌ها.
2. **PFBD (Physical Function Breakdown):** ساختار شکست عملکردهای منطقی به فیزیکی.
3. **PDFB (Physical Data Flow Blank):** جریان داده و تبادلات فیزیکی بین عملکردهای فیزیکی.
4. **PCB (Physical Component Breakdown):** شکست درختی مؤلفه‌ها و نودهای فیزیکی.
5. **PAB (Physical Architecture Blank):** معماری جامع فیزیکی؛ نمایش نودها، مؤلفه‌های رفتاری، استقرارها (`DeploymentLink`)، کابل‌ها (`PhysicalLink`)، تخصیص عملکردها (`Allocation`) و تبادلات (`ComponentExchange` / `PhysicalExchange`).
6. **FC / ES / PS (Functional Chain / Scenario):** سناریوهای زمانی و زنجیره‌های عملکرد فیزیکی.

## ۶. اصول کلی اتصالات و شکست ساختاری (قوانین طلایی پروژه)
1. **حذف مفهوم Composition:** رابطه Composition به عنوان یک یال یا فلش در پالت دیاگرام‌ها وجود ندارد. شکست ساختاری منحصراً از طریق ساختار درختی (Tree) و دربرگیری فضایی (Nesting) در دیاگرام‌های مجاز مدل‌سازی می‌شود.
2. **عدم شکست و عدم اتصال اکتور به اکتور:** هیچ اکتوری (`OperationalActor`, `SystemActor`, `LogicalActor`, `PhysicalActor`) هرگز شکسته نمی‌شود، والد نمی‌گیرد، فرزندی دربرنمی‌گیرد و به یک اکتور دیگر متصل نمی‌شود (اتصال Actor ↔ Actor در تمامی لایه‌ها و دیاگرام‌ها ممنوع است). اکتورها منحصراً با سیستم، موجودیت‌ها، مؤلفه‌ها یا از طریق تخصیص با توابع و قابلیت‌ها در تعامل هستند.
3. **تخصیص فعالیت‌ها/توابع:** فعالیت‌ها و توابع همواره از طریق رابطه تخصیص (**Allocation**) به ساختار مربوطه متصل می‌شوند.
4. **تفکیک کامل دیاگرام‌های معماری (Blank) از شکست (Breakdown):** دیاگرام‌های Architecture Blank نظیر OAB، SAB، LAB و PAB صرفاً جریان ارتباطی و تخصیص را نمایش می‌دهند و روابط ژنرالیزیشن یا شکست ساختاری مختص دیاگرام‌های Breakdown (مانند OEB، LCB، PCB) هستند.
